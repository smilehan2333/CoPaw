# Application Logs Use Async Stdout Pipeline

Swe application logs will use an asynchronous stdout/stderr output pipeline for the `swe` logger namespace while preserving the existing log format and structured telemetry payloads. We will remove the file-backed `swe.log` capability, the `/daemon logs` chat command, the `swe daemon logs` CLI command, and the `SWE_FILE_LOG_ENABLED` switch, because process stdout/stderr is the operational logging boundary and retaining file-log commands would imply a durability contract we no longer want. The async pipeline uses a bounded queue: debug/info records may be dropped with summarized visibility when the queue is full, warning/error/critical records get a short enqueue wait and then best-effort direct stderr fallback, and normal shutdown drains briefly without promising zero loss during hard crashes or forced termination.
