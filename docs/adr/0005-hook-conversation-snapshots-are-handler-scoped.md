# Hook Conversation Snapshots Are Handler-Scoped

Hook handlers that need conversation history receive a bounded Hook Conversation Snapshot through explicit handler configuration, not by reading `transcript_path`, enabling a global hook option, or receiving the full Agent state. The snapshot is captured from current in-memory messages at the Hook Runtime boundary, then exposed only to handlers with `includeConversationSnapshot: true`, with `conversationSnapshotLimit` defaulting to 50 and capped at 200. This keeps in-flight context available to command, HTTP, prompt, and skill-owned hooks while limiting payload size, privacy exposure, and coupling to persistence internals.

Consequences: the snapshot payload uses `conversation_snapshot` and `conversation_snapshot_meta`, excludes reasoning content, keeps normal user/assistant/tool-call/tool-result messages, and represents media or attachments by lightweight references rather than inline content. The current hook event remains represented by existing HookContext fields such as `prompt`, `tool_input`, `tool_response`, `assistant_response`, and `error`; the snapshot does not synthesize or duplicate that event. If agent memory is unavailable, handlers receive an empty snapshot with unavailable metadata instead of causing the hook boundary to fail.
